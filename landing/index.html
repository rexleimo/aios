模型网关

一个网关，通吃所有客户端和模型。

AIOS 在你本机跑一个网关（127.0.0.1:8686，上游 magpie）。请求先从客户端到本机网关，再经网关落到模型；有条件的账号优先、失败后退避并转移，每一次决策都实时写在请求记录里。下图是控制台里真实的路由视图。

一次接入，处处可用

网关把客户端和模型解耦：客户端只认一个本地地址，模型随时可换。

按条件路由

有条件的账号优先；额度、失败退避和上游优先级都参与选路。

决策实时可见

每条请求的路由、命中的模型与状态写进记录，不靠猜。

失败自动转移

出错的账号退避后再试，换到下一个可用账号，不打断你的 Agent。

客户端接入

打开「接入」，网关模型就出现在客户端里。

Agent 客户端页列出本机发现的每个客户端、它的版本与配置落点。给某个客户端选好模型、打开接入，网关的模型就会作为可选项出现在它的列表里。

  • 自动发现 从本机读客户端与版本，不靠一份手填清单。
  • 模型分配 每个客户端单独选「AIOS Auto」或指定模型。
  • 接入开关 写入后会备份配置，需要时可还原。
  • 方案 保存当前设置，之后一键切回。

自适应工作流

按风险选路径，简单任务不排队。

直接、守护、计划三条路径，按任务风险自动选，也能显式指定。高风险改动走策略与验证，简单问答直接给答案——每条消息走哪条路、为什么，都写在上下文里。

直接：最快路径。适合问答、查询和一次性小改动，不做额外编排，直接给出结果。

直接

问答、查询、小改动走最短路径，不做额外编排，延迟最低。

守护

涉及边界、外部副作用或凭据的动作，先过策略门，再放行。

计划

终端

一个命令，贯穿整个工作流。

安装脚本把 aios 放进 ~/.local/bin，aios init --all 在你的项目里写好配置与原生指令。之后记忆、团队、验证都从终端发起。

curl -fsSL https://github.com/rexleimo/aios/releases/latest/download/aios-install.sh | bash

Windows 用 PowerShell 安装，命令一致；装好后在项目根目录运行 aios init --all。

# 初始化与体检
aios init --all                       # 写入配置与十种客户端指令
aios doctor --native --verbose        # 构建/类型/测试/密钥扫描

# 项目记忆
aios memo search "工作流策略"          # 召回之前的裁定与约束
aios session start --json             # 开一个可续做的会话

# 计划与多智能体
aios plan task <id> --confirm-context  # 确认执行上下文
aios team dispatch --items work-items # 派发独立工作项

# 日常
aios work --intent implement          # 让引擎接管一次实现
aios refs read <ref_id>               # 召回被压缩的完整证据
