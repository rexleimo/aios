블로그 허브

AIOS 기술·성장 블로그(한국어판)입니다. 기억 시스템, 단일 agent harness, Agent Team 병렬 협업, 브라우저 자동화, 워크플로 정책, 멀티 클라이언트 운영 실전을 다루며 각 글에 재현 가능한 명령과 검증 증거를 함께 제공합니다.

← 全部文章 · 首页

AI 코딩 에이전트를 더 똑같이, 더 신뢰할 수 있게, 더 쉽게 작업할 수 있게 만드는 스토리, 튜토리얼, 심층 분석.

AIOS는 로컬 agent 워크플로 레이어입니다. 새로운 코딩 에이전트가 아니라 기존 codex, claude, gemini, opencode 에 기억, 팀워크, 자기 진단을 추가하는 레이어입니다.

여기서 시작하기

AIOS를 처음 사용하시나요? 이 게시물들이 방향을 잡아줄 것입니다:

  • AIOS로 Google Harness²를 재현했다 — harness 엔지니어링의 값어치는 몇 점인가 — AIOS 책상을 같은 채점대에서 실측: 맨 51.1 → AIOS 85.8(+34.7pp), 논문값과 우리 트랙의 재귀법 모두 초과
  • AIOS 이야기 — 왜 만들었는지, 어떤 문제를 해결하는지
  • CLI 비교: Raw vs. AIOS — 레이어를 추가하면 무엇이 달라지는지
  • 자동화 플레이북 — 일상적 사용 패턴
  • v4.0 적응형 워크플로 정책 — 라우트와 계획을 고르는 방법
  • AI 에이전트 워크플로는 어떻게 고를까? — 판단표와 실전 예시
  • CLI 명령에서 신뢰할 수 있는 워크플로로 — 반복 가능한 경계 만들기

최신 글

  • v6.7.0: 한 명령, 모든 클라이언트 — 'aios skill add'가 커뮤니티 스킬에 정문을 열어주다 — 가장 쓸모 있는 커뮤니티 스킬이 한 클라이언트의 전역 스킬 디렉터리에만 머물고 나머지 아홉은 볼 수 없었다. aios skill add <source>가 로컬 디렉터리나 git URL을 canonical 외부 레지스트리에 스테이징하고 모든 클라이언트의 사용자 레벨 스킬 루트로 배포한다 — 멱등, fail-closed 선택, 자가복사 가드가 clone-website 원본을 지켰다

  • v6.6.0: 에이전트 작업 공간이 프로젝트 목록에 새었다 — -p 없는 mktemp -d 가 cwd 에 써서 프로젝트 상위에 샌드박스 41 개 (9.9 GB) 가 자랐다. AGENTS.md 로 규칙을 명시하고 scripts/aios-tmp-gc.mjs 는 객관적 사실만으로 회수하며 읽을 수 없는 건 남긴다

  • v6.5.0: OpenCode 2.x 플러그인 계약, 그리고 AIOS의 위치를 거짓으로 적지 않게 된 설정 — OpenCode 2.x는 default export만 읽어 AIOS 플러그인이 조용히 죽어 있었다. 1.x/2.x dual export화와 설치 시 자기 복구, aios interception mcp-repair로 무효 MCP 경로를 안정 runtime root로 되돌린다

  • 한 문장의 요구, 하나의 소프트웨어: 소형 모델이 한 달에 36억 토큰 — AIOS가 '누구나 개발할 수 있다'를 현실로 — 필요한 새 기술은 하나뿐이다, 요구를 명확히 말로 정리하는 것. 캐시 히트 96%의 한 달 고강도 사용, 맨 모델 vs AIOS 비교, 요구부터 납품까지의 흐름이 만든 E:/coding 프로젝트 목록

  • v6.4.0: 추측하지 않는 컨트롤 플레인 — 원장은 갈라지지 않고, 거절은 기능이고, 게이트는 선언된 곳에서 돈다 — 계획 원장은 갈라지지 않는다(A21–A23), plan CLI는 읽기 전용 뷰로 치환하는 대신 거절한다(A19), 선언된 검사는 CI에서 돈다(A20 + 디렉터리 예산 + 영향 테스트), mattpocock v1.3 트리오 양면 채택

  • v6.3.0: /grill이 진짜 커맨드로, 인터뷰는 스스로 기록하고, pi는 자기 MCP 캐리어를 고른다 — 청취 커맨드가 드디어 일곱 클라이언트에 등록되고, 확정된 용어는 CONTEXT.md로 결정은 ADR로. pi 0.99+는 버전으로 MCP 캐리어를 골라 시작 경고를 쌓지 않습니다

FAQ

어디서 시작해야 하나요?

먼저 AIOS 이야기를 읽고, 퀵스타트 가이드를试试하세요.

기억과 컨텍스트 관리가 중요하다면?

Token 압축에서 시작해서 ContextDB 검색을 읽어보세요.

에이전트를 밤새 실행하고 싶다면?

Solo Harness를 읽고 Solo Harness 문서를 확인하세요.

에이전트가 스스로 디버깅하게 하고 싶다면?

debug-hub를 읽고 debug-hub 문서를 확인하세요.

AIOS는 새로운 코딩 에이전트인가요?

아닙니다. codex, claude, gemini, opencode 를 감싸서 기억, 팀워크, 자기 진단을 추가합니다. 워크플로우는 변하지 않습니다.
