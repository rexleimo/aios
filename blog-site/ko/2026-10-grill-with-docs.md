# v6.3.0: /grill이 진짜 커맨드로, 인터뷰는 스스로 기록하고, pi는 자기 MCP 캐리어를 고른다

> **Quick Answer:** 하나의 릴리스에서 두 가지 수정. 첫째, AIOS의 요구사항 청취 커맨드 `/grill`은 워크플로 코어에는 실재했지만 어디에도 등록되어 있지 않았습니다. 어떤 클라이언트도 자동완성하지 않았고, 파싱하는 것은 Claude Code의 hook뿐이었습니다. 이제 일곱 클라이언트에 등록된 얇은 스킬이 되었고, 그 뒤의 규율도 빠져 있던 절반을 채웠습니다. 확정된 도메인 용어는 실시간으로 `CONTEXT.md` 용어집에, 기울어진 결정은 `docs/adr/` 아래의 경량 ADR로 기록됩니다. 둘째, pi 0.99+는 자체 내장 MCP 확장을 함께 실어 오고, 별도 설치한 `pi-mcp-adapter`와 충돌해 매 시작마다 경고를 출력했습니다. 설치 관리자가 이제 pi 버전을 읽고 캐리어를 고릅니다. 새 pi는 내장 MCP, 어댑터는 레거시 폴백으로만 — 그리고 둘은 같은 `mcp.json`을 읽습니다.

## 문제: 입력할 수 없는 커맨드, 기억을 잃는 인터뷰

aihero.dev의 `/grill-with-docs` 글은 에이전트가 계획에 대해 청취하고 배운 것을 기록하는 방식을 소개했습니다. 용어는 `CONTEXT.md`로, 결정은 ADR로. 그것을 우리 구현과 나란히 놓고 보니 점수는 유쾌하지 않았습니다.

**청취 절반은 이미 갖고 있었습니다.** `rex-requirements`는 작업 중에 인라인으로 청취합니다. 의사결정 질문을 한 번에 하나씩, 모든 질문에 권장 기본값을 붙여, 3라운드 예산으로 답 없는 실은 막는 대신 기록된 가정으로 바꿉니다. 그러나 **적어 두는** 일은 결코 없었습니다. `CONTEXT.md`가 있으면 읽었지만, 쓰는 것은 리포지토리 어디에도 없었고, 청취를 통과한 결정은 휘발성 플랜 상태에 머물렀습니다.

**커맨드 절반은 더했합니다.** `/grill` — `/plan`, `/spec`, `/tickets` 가족 전체가 — 는 텍스트 관례에 불과했습니다. 워크플로 코어의 정규식 하나, AGENTS.md의 선언 프로토콜, Claude Code에 연결된 UserPromptSubmit hook. ZCode에서 `/grill`을 입력해도 자동완성은 아무것도 제안하지 않았습니다. 등록된 것이 없었기 때문입니다.

그리고 pi 0.99+ 머신에는 세 번째 성가심이 있었습니다. pi는 2026-09-29에 내장 `mcp` 확장을 함께 실어 왔고, AIOS는 그 위에 서드파티 `pi-mcp-adapter`를 계속 설치했으며, 둘 다 `/mcp`를 등록하고, pi는 매 시작마다 `[Extension issues]` 경고를 출력한 뒤 조용히 어댑터를 골랐습니다.

## 바뀐 것

### /grill이 등록된 스킬로

`skill-sources/grill/SKILL.md`는 얇은 진입점입니다. `explicit-intent: grill`을 선언하고, rex-requirements 플로우를 실행하고, 그 기록 규칙을 수행합니다. 프로세스 세부는 일부러 담지 않습니다. 불일치하면 rex-requirements가 이깁니다. 규율은 한 곳에만 삽니다. 빌드는 모든 리포지토리 표면(`.codex/skills`, `.claude/skills`, `.agents/skills`…)에 materialize하고, frontmatter가 약속한 일곱 클라이언트(zcode, codex, claude, pi, qoder, hermes, workbuddy) 홈에 설치합니다. 새 세션에서 `/`를 입력하면 거기 있습니다.

### 인터뷰는 스스로 적어 둡니다

`rex-requirements`에 "수용 기준 기록"과 "첫 슬라이스" 사이에 한 단계가 추가되었습니다. **그 자리에서 리포지토리에 기록하기**. 답변이 도메인 용어를 확정하는 순간 에이전트는 리포지토리 루트의 `CONTEXT.md` 용어집에 즉시 upsert합니다. 정의 한 줄, 이유 한 줄. 사용자가 직접 쓴 항목은 절대 다시 쓰지 않습니다. 예산을 통과했거나 명시적으로 결정된 사안은 `docs/adr/NNNN-<slug>.md`가 됩니다. 배경·결정·결과, 번호는 재사용하지 않습니다. 경계는 규칙에 새겨 있습니다. 기록된 가정은 검증되지 않았으며 결코 ADR이 되지 않고, 기울어진 결정만이 됩니다.

이것은 두 번째 기억 시스템이 아닙니다. 세션 간 기억은 여전히 ContextDB 레인에 있습니다. 풀 기반이고, 강력하며, recall이 빗나가면 침묵합니다. `CONTEXT.md`와 ADR은 보완 레인입니다. 코드와 함께 버전 관리되고, 아무도 요청하지 않아도 미래의 모든 에이전트와 사람의 눈에 보입니다. 다른 질문에는 다른 저장소.

### pi는 자기 버전으로 MCP 캐리어를 고른다

`resolvePiMcpMode()`는 `pi --version`을 읽어 pi ≥ 0.99.0이면 `builtin`, 아니면 `adapter`를 돌려줍니다. 버전 감지에 실패해도 `adapter`로 떨어집니다. 항상 안전한 레거시 경로이므로 오프라인 머신도 오래된 pi도 이전과 바이트 단위로 같게 동작합니다. 두 캐리어는 같은 `~/.pi/agent/mcp.json`을 읽으므로 AIOS가 관리하는 서버 항목은 캐리어와 무관하고, 서버는 하나도 움직이지 않습니다. 새 pi에서는 설치 관리자가 어댑터를 설치하지 않습니다. 이미 설치된 어댑터는 **보고만** 됩니다(`installed-conflicts`, info 수준, 선택적 `pi remove npm:pi-mcp-adapter` 포함). 제거는 세션 동작을 바꾸므로 대신 하지 않습니다. `aios doctor`도 같은 분기를 반영해 새 pi에서 "Pi가 MCP 서버를 로드할 수 없다"는 잘못된 경고를 내지 않습니다.

## 업그레이드 노트

- `/grill`에는 마이그레이션이 없습니다. `aios init`을 다시 실행(또는 pull 후 스킬 재동기화)하면 나타나고, 그 전에는 기존 텍스트 관례 경로가 그대로 동작합니다.
- `CONTEXT.md` / `docs/adr/`는 첫 사용 시 생성되며 프로젝트와 함께 커밋해야 합니다. 가치는 코드와 함께 버전 관리되는 데 있습니다.
- pi ≥ 0.99.0의 시작 경고는 정보 수준이며 무해합니다. 어댑터는 그대로 동작합니다. 제거(`pi remove npm:pi-mcp-adapter`)는 선택 사항이며, 그 후 내장 MCP로 돌아갑니다. `pi mcp list`를 한 번 보고 결정하면 충분합니다.
