# v1.40: AI 코딩 클라이언트를 6개로 확장한 이유

> **Quick Answer:** v1.40은 Harness CLI의 지원 범위를 4개 클라이언트에서 6개로 넓히며 Antigravity CLI와 Crush를 추가했습니다. 각 클라이언트의 인터페이스는 달라도 Skills, 워크플로, 검증에 대한 공통 계약을 유지하는 것이 목표였습니다.

이 글은 v1.40 시점의 확장을 기록합니다. 현재 지원 클라이언트와 설치 방법은 최신[빠른 시작](https://cli.rexai.top/ko/getting-started/)과[아키텍처](https://cli.rexai.top/ko/architecture/)를 우선해서 확인하세요.

## 클라이언트를 늘리는 이유

AI 코딩 현장에서는 팀과 개인이 하나의 CLI만 사용하지 않습니다. 모델, 인증, 터미널 경험, 비용, 확장 기능에 따라 선택이 달라집니다. 필요한 것은 모든 클라이언트를 똑같이 만드는 일이 아니라 프로젝트의 안전 경계를 공유하는 일입니다.

v1.40에서 추가한 클라이언트는 다음 두 가지입니다.

- Antigravity CLI;
- Crush。

덕분에 클라이언트를 바꾸어도 Skills의 위치, 워크플로 분류, 검증 원칙을 같은 방식으로 설명할 수 있게 되었습니다.

## 공유한 계약

### Skills

프로젝트별 절차는 각 클라이언트가 찾을 수 있는 repo-local skill로 관리합니다. 클라이언트 설정 파일에 절차를 복사하기보다 변경 원본을 하나로 유지하는 방식입니다.

### Workflow

질문, 읽기 전용 조사, 작은 변경, 여러 단계 작업을 구분합니다. 모든 클라이언트가 같은 분류를 사용하면 클라이언트를 바꾸어도 안전성 기대치가 달라지지 않습니다.

### Verification

클라이언트가 달라져도 변경 표면에 맞는 테스트와 build를 실행합니다. 성공한 프로세스 화면만으로는 공개 문서, 내비게이션, 외부 의존성의 사용 가능성까지 증명할 수 없습니다.

## 도입 체크리스트

1. 지원 클라이언트를 설치합니다.
2. `aios init --all`을 실행해 공통 설정을 확인합니다.
3. `aios doctor --native --verbose`로 로컬 상태를 확인합니다.
4. 작은 읽기 전용 작업으로 Skills와 라우트를 확인합니다.
5. 변경할 때는 편집 게이트와 최종 검증을 통과합니다.

클라이언트와 provider의 live 사용 가능성은 별도로 확인해야 합니다. dry-run이나 로컬 doctor가 성공해도 로그인 상태나 외부 서비스까지 보장하지는 않습니다.

## FAQ

### 6개 클라이언트가 같은 모델을 써야 하나요?

아닙니다. 공유하는 것은 모델이 아니라 프로젝트의 워크플로와 안전 계약입니다.

### 클라이언트를 늘리면 설정이 복잡해지지 않나요?

공통 repo-local skill과 검증 표를 중심에 두면 클라이언트별 설정 차이를 작게 유지할 수 있습니다. 현재 분류는[워크플로 정책](https://cli.rexai.top/ko/workflow-policy/)에서 확인하세요.

### 현재 클라이언트 목록은 어디서 보나요?

최신[빠른 시작](https://cli.rexai.top/ko/getting-started/)과 저장소 changelog를 확인하세요.
