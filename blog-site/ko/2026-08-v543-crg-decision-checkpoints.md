# v5.4.3: CRG 결정 체크포인트, Worker Journal 이름 변경, 멱등한 `aios init`

> **빠른 답변:** v5.4.3은 워크플로 레이어를 구조적으로 더 안전하게 만드는 소규모 릴리스입니다. `aios-workflow-router`와 `rex-workflow`는 이제 code-review-graph(CRG) 결정 체크포인트를 실행합니다——편집 전 영향 범위 확인, 코드 변경 전 테스트 존재 확인, 각 단계 종료 후 실제 변경 검증——그리고 CRG가 설치되지 않은 경우 `rg` + 파일 읽기로 우아하게 폴백합니다. solo harness 저널 디렉터리는 `solo-harness` → `worker-journal`로 이름이 바뀌었고(기존 디렉터리는 자동 마이그레이션), `aios init`에는 `--yes` / `--retry` / `--force`가 추가되어 멱등한 설정/업데이트가 가능해졌습니다.

## 결정 체크포인트가 왜 중요한가

의존 관계를 보지 않고 코드를 편집하는 에이전트는 조용한 회귀(regression)의 1순위 원인입니다. 기존 워크플로는 에이전트에게 *무엇을* 할지(계획·구현·검증)만 알려줬지, 건드리기 전에 *어떻게 살펴볼지*는 알려주지 않았습니다. v5.4.3은 워크플로 스킬에 4가지 CRG 체크포인트를 연결해 이를 해결합니다:

1. **작업 전** — `get_minimal_context`가 약 100토큰으로 프로젝트 컨텍스트와 다음 단계를 제시합니다.
2. **편집 전** — `get_impact_radius`가 변경 대상 파일의 폭발 범위를 확인합니다. `query_graph(tests_for)`가 테스트 존재를 확인합니다(없으면 먼저 테스트 작성).
3. **코드 검색 시** — `semantic_search_nodes` / `query_graph`가 무작정 grep + 읽기를 대체해 더 빠르고 토큰도 절약합니다.
4. **각 단계 종료 후** — `detect_changes`가 실제 영향이 의도와 일치하는지 검증합니다(자기 보고가 아닌).

프로젝트에 CRG가 없으면 그 사실을 기록하고 `rg` + 파일 읽기로 폴백합니다——워크플로를 차단하지 않고 그래프 증거를 위조하지도 않습니다.

## Worker Journal 이름 변경

solo harness 저널 디렉터리는 기존 모듈 명명(`solo-journal`)에 맞춰 `solo-harness`에서 `worker-journal`로 변경되었습니다. 세션 산출물은 `artifacts/worker-journal/`에 위치합니다. 기존 `solo-harness` 디렉터리는 첫 읽기 시 자동 마이그레이션되며——수동 조작도 데이터 손실도 없습니다——solo worktree 임시 접두사도 새 이름을 따릅니다.

## 멱등한 `aios init`

`aios init`는 이제 다음 옵션을 지원합니다:

- `--yes` — 대화형 확인 생략(CI / 무인 설치).
- `--retry` — 아직 설치되지 않은 컴포넌트에서 재개.
- `--force` — 이미 설치되어 있어도 전부 재설치.

이 옵션들은 새로운 `install-state` 모듈이 뒷받침하며, 컴포넌트 설치 상태를 추적하므로 중단된 설정은 처음부터 다시 시작하는 대신 재개할 수 있습니다.

## 무엇을 해야 하나

- 기존 설치본: `aios update`만 실행하면 끝입니다. 이름 변경 마이그레이션은 자동입니다.
- 스크립트나 CI에서 `aios init`을 실행한다면 `--yes`로 대화형 프롬프트를 생략할 수 있습니다.

## FAQ

### 이 릴리스가 CRG 도구 자체를 바꾸나요?

아니요. code-review-graph MCP 서버는 변하지 않습니다. v5.4.3이 바꾼 것은 워크플로 레이어가 언제, 어떻게 이를 호출하는지입니다. CRG를 설치하지 않아도 기존과 동일하게 동작합니다.

### 기존 `solo-harness` 세션 데이터가 유실되나요?

아니요. 마이그레이션은 첫 읽기 시 디렉터리 이름을 바꾸고 모든 파일을 보존합니다. 이전 이름은 레거시 조회로만 사용됩니다.

### 세부 내용은 어디서 볼 수 있나요?

[변경 로그](https://cli.rexai.top/changelog/)에 v5.4.3이 모든 로케일로 기록되어 있습니다.

"변경하려는 것"과 "변경된 것의 검증" 사이의 루프를 소규모 릴리스로 조이면, 장기 실행 에이전트 작업의 신뢰성이 크게 높아집니다.
