# 自动化运营实践：搭建可靠的浏览器内容工作流

> **快速答案：** 可靠的浏览器内容运营，应把规划、起草、人工审核、发布和测量拆成可观察的阶段。使用可见的 CDP 浏览器和明确的 MCP 操作，把账号登录留在浏览器配置中，并将结果写入可检索的项目上下文。自动化应该减少重复点击，而不是移除责任边界。

很多人把浏览器自动化理解成宏：打开页面、点击按钮、粘贴文案，然后重复。真正容易出问题的地方却是：哪一条内容已经批准、当前使用的是哪个账号、发布是否成功，以及浏览器或网络失败后如何继续。

下面这套流程把“宏”拆成一个可暂停、可审核、可恢复的小型运营系统。

## 一页看懂工作流

| 阶段 | 系统负责 | 人负责 |
| --- | --- | --- |
| 规划 | 维护选题队列和状态字段 | 确定目标、受众和发布边界 |
| 起草 | 生成初稿、变体和来源引用 | 校对事实、语气和原创性 |
| 审核 | 阻止未批准内容进入发布队列 | 审核最终文案和媒体素材 |
| 发布 | 操作可见浏览器并报告结果 | 处理认证墙和敏感外发操作 |
| 测量 | 记录时间戳和结果指标 | 解读数据并决定下一次实验 |

建议使用明确的状态流转：`idea -> draft -> review -> approved -> published -> measured`。浏览器动作失败不等于内容被拒绝，因此要把“内容状态”和“运行结果”分开记录。

## 1. 先建内容队列，再写自动化步骤

每条内容使用一个稳定记录，至少包含：

- 内容 ID、目标平台和账号标签；
- 主题、受众和希望用户采取的动作；
- 文案草稿、媒体引用和来源；
- 审核状态、审核人和审核时间；
- 计划发布时间与实际发布时间；
- 结果指标、观察窗口和后续备注。

队列让任务可以恢复。如果浏览器在第 12 条内容后关闭，下一次运行可以查询 `approved` 项，而不是让代理从一段聊天记录里猜测进度。

## 2. 使用可见、边界清晰的浏览器循环

浏览器工作优先使用仓库推荐的 browser-use CDP 路径：

1. 使用目标浏览器配置启动可见浏览器。
2. 通过 CDP 连接到浏览器。
3. 先读取语义快照或相关页面文本。
4. 执行一个可见动作。
5. 等待预期的状态变化。
6. 重新读取页面并记录结果。

认证墙、账号切换、最终发布和其他敏感外发动作应保留人工协同。不要尝试隐藏自动化、变换身份或规避平台控制，也不要把操作节奏调整描述成合规保证。平台提供官方 API 或批准的自动化能力时，应优先遵守对应规则，并保留人工复核。

## 3. 让审核真正成为门禁

发布动作不应只依赖一个容易被忽略的复选框。最小发布条件可以写成：

```text
status == approved
reviewer != empty
media references resolve
target account matches the selected profile
```

任何条件不满足，都应停止并标记为 `blocked`，同时报告下一步安全动作，而不是悄悄把检查降级为提示。这和 AIOS 的最小正确变更门禁是同一个原则：安全边界必须可观察、可执行。

## 4. 用 ContextDB 保存有用上下文

ContextDB 适合保存长期有效的事实、内容队列状态、来源引用和交接记录。基于拉取的工作流只检索下一步需要的证据，不把全部历史对话塞进每一次操作。

可从 [ContextDB 文档](https://cli.rexai.top/zh/contextdb/) 了解项目记忆和检索；本文对应的检索实现见 [ContextDB FTS5/BM25 文章](contextdb-fts-bm25-search.md)。不要把个人数据、凭据、Cookie 或未脱敏的授权日志写入公开产物。

## 5. 用统一口径测量结果

每个平台和每条内容尽量记录同一组字段，例如曝光、阅读、点赞、收藏、评论、关注、点击，以及从审核通过到发布的耗时。必须记录观察窗口，不能把发布两小时的数据和发布七天的数据直接比较。

Perception 可以帮助总结结果，但它不替你决定事实，也不应该自动发布下一条变体。下一次实验要明确一个假设、一个变化变量和一个观察窗口。

## 中断后的恢复清单

任务停止后，先分类再重试：

- `blocked`：需要人工审批、登录或策略判断；
- `failed`：内容或请求本身无效；
- `infra-retry`：浏览器、工具或网络可能恢复；
- `published`：已验证发布成功；
- `measured`：已记录观察结果。

交接记录应包含最后页面状态、账号标签、内容 ID 和下一步安全动作。这样换人或换客户端时不需要猜测。

## 常见问题

### 可以完全不经人工审核就发布吗？

只有当平台规则、账号所有者授权和项目策略都明确允许时，才可以考虑更高程度的自动化。默认流程保留审核和敏感外发动作的人机协同。

### 一开始就同时运营多个账号吗？

不建议。先用一个账号验证队列、审核和恢复模型；只有在状态可观察、账号边界清晰且符合平台规则后，再增加隔离的浏览器配置。

### 最小可用配置是什么？

一份内容队列、一个可见的 CDP 浏览器配置、一个审核门禁和一份结果记录就足够开始。内容量增加后，再加入 ContextDB 检索和 Perception 汇总。

### 自动化能替代官方平台接口吗？

不能一概而论。优先使用平台提供的官方接口或批准的自动化方式；浏览器自动化只应在授权范围内运行，并保留认证墙和敏感操作的人为确认。
