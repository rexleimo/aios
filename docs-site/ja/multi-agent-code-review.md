# マルチエージェントコードレビュー：本当に役立つ並列コーディングエージェント

> **まず答え：** 並列コーディングエージェントがコードレビューで役立つのは、次の 3 つが成り立つときだけです：作業が独立したノードに分割されている、各ノードが分離された worktree に書き込む、マージステップが生の意見ではなく検証済みの証拠を消費する。AIOS の Agent Team（`aios team 3:codex "Review the auth module"`）は N 個のエージェントを並列にディスパッチし、バリアで待ち、フィルタと合成ができる結果セットを返します——途中には HUD ステータスと証拠ゲートが付きます。

## ナイーブな並列エージェントが失敗する理由

調整なしに 3 つのエージェントを同じコードベースに送ると、次のことが起きます：

- **作業の重複** — スコープを分割するものが何もないため、3 つすべてが同じファイルをレビューする。
- **状態の衝突** — 2 つのエージェントが同じツリーに競合する変更を書き込む。
- **検証不能な結果** — 各エージェントがチェックできない自由形式の意見を返す。

グラフエンジニアリングの教訓がそのまま当てはまります：並列ノードには契約、分離、そして欠損入力を許容できるマージステップが必要です。

## 信頼できるパターン：扇出、分離、検証、マージ

1. **スコープを分割する** — 各エージェントが有界な割り当て（モジュール単位、ルート単位、リスククラス単位）を受け取る。
2. **作業を分離する** — 各エージェントが自分の git worktree で実行するため、書き込みが衝突しない。
3. **バリアで待つ** — チームはすべての結果を待つ。失敗したエージェントは `null` になり、バッチ全体をブロックしない。
4. **フィルタとマージ** — 失敗を落とし、発見を重複排除し、合成ノードが収集した証拠から最終レビューを書く。

## マルチエージェントレビューの実行方法

```bash
# 1. Initialize AIOS
aios init --all

# 2. Fan out three agents on an independent scope
aios team 3:codex "Review the auth module: check validation, session handling, and test coverage"

# 3. Track status and evidence
aios team status

# 4. Merge and verify before acting
aios doctor --native --verbose
```

各エージェントは証拠付きでチーム HUD に報告します。合成ステップが見るのは検証済みの結果だけです。worker の規約と watchdog の動作は [Agent Team ドキュメント](https://cli.rexai.top/ja/team-ops/) を参照してください。

## FAQ

**並列エージェントは何個実行すべきですか？**
まず 2〜3 個から始めます。並行度はコア数と、作業がどれだけきれいに分割できるかで制約されます。サブタスクが本当に独立している場合にだけ、エージェントを増やす効果があります。

**1 つのエージェントが失敗したらどうなりますか？**
バッチ全体をブロックせずに失敗結果になります——それをフィルタしてそのノードを再ディスパッチするか、残りのノードがスコープをカバーしていれば部分結果セットを受け入れます。

**並列エージェントに別々の git ブランチが必要ですか？**
worktree 分離が安全なデフォルトです：各エージェントが自分のチェックアウトを持ち、受け入れられた証拠だけがマージされます。
