# Shell Shim Baked Root Guard — Test Scope Contract

- Work item: `shell-shim-baked-root-guard`
- Date: 2026-09-18
- Capability: `software.testing.design` (`rex-test-design`)
- Incident reference: `~/.aios/bin/{aios,claude,...}` shipped with
  `_aios_root_baked='D:\Temp\aios-shell-runtime-root-4jX3tx'` (a dead test temp
  root) while `aios doctor` still reported `[ok] native shim installed`.

## 1. User goal

A native shim whose baked runtime root no longer resolves must be **visible**,
and re-running the shell setup must **repair** it.

## 2. Explicit non-goals

- No change to the shim templates' runtime semantics (`AIOS_ROOT_DIR` precedence,
  probe fallback list, `exec node ...` line).
- No change to which commands get shims, the shim directory, or `PATH` handling.
- No automatic background repair outside the existing `aios setup` /
  `installContextDbShell` path.
- No change to `mcp-server/` or rex-harness.

## 3. In-scope behavior (changed)

| # | Behavior | Observable signal |
|---|---|---|
| B1 | `aios doctor` reports a stale baked root in an installed managed shim | a `[warn]` line naming the shim path and the unresolvable baked root |
| B2 | `aios doctor` stays quiet for a shim whose baked root resolves | `[ok] native shim installed: <path>` and no stale-root warning |
| B3 | `installContextDbShell` (i.e. `aios setup --components shell`) rewrites a stale managed shim for the current platform with the current runtime root | shim file content changes; its baked root resolves after setup |

## 4. Out-of-scope behavior (unchanged, must not regress)

| # | Behavior | Guard |
|---|---|---|
| O1 | Refusal to overwrite an unmanaged (marker-less) shim | existing error `Refusing to overwrite unmanaged native shim(s)` |
| O2 | `uninstallContextDbShell` removes only marker-bearing shims | existing uninstall test |
| O3 | Doctor count contract (`effectiveWarnings` / `warnings`) used by `aios doctor` aggregation | stale-root warning must not turn an otherwise-healthy install into an effective failure |

## 5. Allowed test seams

- `doctorContextDbShell({ rootDir, platform, homeDir, rcFile, env, io })` —
  exported public entry used by `aios doctor`; `io.log` capture is the
  established seam (`scripts/tests/aios-components.test.mjs`).
- `installContextDbShell({ rootDir, platform, homeDir, rcFile, commandRunner })`
  with an isolated temp `homeDir` — established seam; a non-existent `rcFile`
  keeps the fixture free of real profiles.
- `uninstallContextDbShell({ platform, homeDir })`.

No private helper is used as the primary assertion surface. Fixtures write shim
files only under a `mkdtemp` `homeDir`.

## 6. Acceptance behavior → observable assertion mapping

| Acceptance behavior | Assertion |
|---|---|
| B1 | After planting a managed shim whose baked root is a removed temp dir, doctor output matches `/\[warn\].*stale|unresolvable/i` **and** names that shim path. |
| B2 | After `installContextDbShell({ rootDir: <live root with scripts/aios.mjs> })`, doctor output contains no stale-root warning and contains `[ok] native shim installed: <shim path>`. |
| B3 | Read the stale shim before/after `installContextDbShell`; assert the baked root in the rewritten file resolves to the live `rootDir`. |

Every assertion observes user-visible doctor text or shim file content; none
counts internal calls.

## 7. Minimal vertical slice

One fixture = one temp `homeDir` + one temp runtime root containing
`scripts/aios.mjs` + one planted managed shim with a dead baked root.

Why this is representative: it reproduces the incident end-to-end through the
public entries (`doctor` observation, `setup` repair) without touching the real
`~/.aios/bin`, and it fails for the exact reason the incident stayed invisible
(doctor had no baked-root check).

## 8. Completion criteria (accepted)

- B1, B2, B3 each have a passing automated test in
  `scripts/tests/aios-components.test.mjs`.
- O1, O2, O3 remain green.
- `npm run test:scripts` green.
- Doctor warning is non-effective (`{ effective: false }`) so a shim that still
  works through probe fallback does not fail `aios doctor`.

## 9. Negative clauses (must not happen)

- No false positive: a shim generated by `installContextDbShell` immediately
  followed by doctor must not warn about a stale baked root.
- No warning for a shim whose baked root uses `${HOME}` and resolves.
- No test may assert absence by deleting/skipping existing cases, loosening
  expectations, or asserting only on mocks.
