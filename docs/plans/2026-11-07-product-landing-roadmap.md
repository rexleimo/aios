# AIOS 桌面版：产品问题与改进计划（2026-11-07）

> 状态：计划，未执行。本文回答两个问题：为什么作者自己用着不错，市场反馈却弱；接下来产品该怎么改。
> 执行方式（交给 pi 编码、由你发起）放在附录，不是本文主体。
> 标「假设」的内容没有数据支撑，需要第 7 节的用户验证来确认或推翻。

## 1. 结论

作者自己觉得好，是因为作者机器上已经有一套装好的 AIOS 仓库，还有一堆真实需要整理的 AI 工具配置、MCP 服务和项目记忆，示例数据背后对应什么，作者心里有数。

新用户的体验完全不同：装不上；就算装上，首屏是示例数据，点下去只是页面内模拟，刷新就没了；界面没有说清楚它替用户解决哪个具体问题。

所以眼下的产品力问题不在技术，而在三件事：
1. 用户看不到**自己的**东西（示例数据冒充真实状态）。
2. 用户**用不起来**（安装依赖开发环境，没有签名）。
3. 用户**得不到结果**（只能看，不能修，管理配置本身也不是高频、高痛的任务）。

## 3. 根因

把上面七条串起来，只有一条因果链：

**取数慢（9.3s）→ 首屏填不满 → 只好用示例数据顶上 → 用户看出是假的 → 不信任 → 不付费。**

不是七个独立问题，是一个问题长出的七片叶子。**「示例数据」不是设计失误，它是 9.3 秒的止痛药。**只要真实取数还这么慢，杀掉示例数据就会换来一个空白的首屏，结果更糟。

再往上追一层，是任务选错了：

- 这个产品替用户做的是**清洁工的工作**——整理配置、梳理 MCP、归档记忆。
- 清洁工任务的前提是**用户已经有一屋子脏东西**。作者机器上有 13 个客户端的配置、若干 MCP 服务、几个项目的记忆，脏东西是真的，所以作者用着爽。
- 新买家买的时候，屋子里是空的。他打开产品，看到的是一份「你还没有东西可以管理」的清单，加一堆示例。

所以市场反馈弱不是执行差，是**卖的是善后服务，却按新装服务的场景在获客**。

还有一个隐性问题：**产品交付的是「状况」，不是「结果」。**即使把数据接真、把页面做漂亮，用户拿到的仍然是「你有 3 个 MCP 服务，其中 1 个连不上」。这句话不构成价值，构成价值的是「我已经帮你修好了，现在能连上」。只读面板性质上是**仪表盘**，仪表盘只在用户已经长期使用某项东西后才有意义。

## 4. 目标买家与任务

三个候选，只能选一个：

| 候选 | 是谁 | 为什么可能付费 | 风险 |
|---|---|---|---|
| A 个人 AI 重度用户 | 同时用 2 个以上 AI 客户端、装过 MCP、有多个项目记忆的开发者 | 配置真实混乱，痛感真实，已经在花时间手工维护 | 人群小；他可能觉得「我自己能改文件，凭什么付钱」 |
| B 工程团队 | 要把团队的 AI 工具配置标准化、统一记忆的团队 | 有采购预算，痛点从「烦」升级为「治理」 | 需要服务端、权限、审计，产品形态整个换一次 |
| C AI 新手 | 刚接触 AI 工具、希望被带着走的人 | 人群最大 | 他没有配置可管，产品对他完全为空；而且他今天用的是网页版，不装桌面软件 |

**建议选 A，并把任务收窄成一句话：**

> 让一个已经在用两个以上 AI 客户端的开发者，在 5 分钟内看清本机所有 MCP 服务和配置的真实状态，并且能就地修好其中坏掉的那个。

判断标准就一条：**用户修好之后，不需要再打开任何配置文件。**做到这条，「管理」就从仪表盘变成了工具。

> **假设（无数据）**：A 人群愿意为「跨客户端统一管理 + 一条命令修好」付费。这条必须由第 7 节的验证来确认或推翻，不能默认成立。B 的采购意愿也同理，目前一个字的数据都没有。

## 5. 改进项（按优先级）

顺序由第 3 节的因果链决定：先解决「慢」，才能去掉「假」；先能「装上」，用户才看得到「真」；有了「真」，「能修」才有意义。

### P0-1 首屏取数提速：先把 9.3 秒降下来

- **改什么**：首屏不再等完整的 `aios status --json`。改成分级采集：先读配置文件是否存在、MCP 服务清单（纯文件读取，预期亚秒级），再后台跑连接测试等慢项，逐项回填。
- **为什么**：这是示例数据存在的根本理由（第 3 节）。不先做这条，P0-2 会让首屏变成空白。`README.md:214-217` 已经写明「要压它得改 `aios status` 本身」。
- **验收**：冷启动到首屏出现**至少一条用户本机真实数据**的时间 ≤ 2 秒（在作者机器和一台干净机器上各测一次）。慢项在页面上标「检测中」，不标「示例」。

### P0-2 杀掉示例数据，接上真实接口

- **改什么**：`home-workspace.tsx`、`mcp-workspace.tsx`、`memory-workspace.tsx`、`console-workspace.tsx`、`flows/memory-detail.tsx`、`flows/mcp-wizard.tsx`、`app/(console)/page.tsx` 不再引用 `demo-data.ts`，改走 `ui/src/app/api/` 下已有的 `mcp`、`memory`、`manage`、`sessions` 路由。全部完成后删除 `demo-data.ts`。
- **为什么**：问题 1、2、7 的直接来源。后端能力已经在，`README.md:5` 自己承认「尚未接到新界面」。
- **验收**（2026-11-07 P0-2 交付后回写，原标准不可执行）：不用 `grep "示例\|模拟"` 当门——它数的是**词**，而这个仓库里两类合法文本永远会让它 nonzero：（a）界面文案里否定式描述（「不写示例」「不在页面里模拟」）；（b）**用户自己的真实 memo 正文**（本机就有一条写「Console A 交互原型…示例数据仅保存在 React 状态」，它出现在记忆列表里）。词级 grep 要么需要删用户记忆，要么永远红——都不是验收。
  实际可执行的结构门，三条已全部成立：
  1. `apps/shell/ui/src/components/console/demo-data.ts` 与 `flows/service-state.ts` **不存在**；
  2. `grep -rn "demo-data|service-state" apps/shell/ui/src` = 0 命中（连类型导入都没有）；
  3. 壳层不得持有临时适配器（`toPrototypeProject` 已删），且每个面板的数字只能来自 `ConsoleFacts`——由 `shell-labels.test.mjs` 「the fixture state is gone from the shipped UI, not just hidden」钉住。
- 刷新页面后数据不变（采集幂等；实测服务数从 79 变 80 是因为配置真变了，不是页面自己搅动）；空状态（用户没装任何客户端）有明确文案和下一步，不显示假数据。
- **约定不变**：`README.md:79` 的第一条约定（真实事实与示例分开）从「示例集中在一处」改写成「没有示例」。

### P0-3 能装上：签名 + 自带运行时

- **改什么**：关掉 `README.md:178` 那个未决产品决定，答案是**壳自带 Node 运行时和已构建的界面**，不再向上找 `scripts/aios-ui.mjs`。`tauri.conf.json` 加 Windows 代码签名；macOS 做签名和公证。
- **为什么**：问题 4。今天的安装包（`README.md:175-176`）要求目标机器上有一份装好依赖并构建过的 AIOS 树，等于只有作者本人能装。没有签名，Windows SmartScreen 会拦截，绝大多数用户在这一步离开。
- **验收**：一台没有 Node、没有 git、没有 AIOS 仓库的干净 Windows 虚拟机上，双击安装包 → 不出现 SmartScreen 警告 → 打开后看到本机真实数据。全程 ≤ 3 分钟，零命令行。
- **代价（需拍板）**：安装包会从 1.84 MiB 涨到几十 MiB（`README.md:172` 实测带 Next 产物是 90.16 MiB，只带运行所需部分会小一些，具体数字未测）。签名证书有年费。

### P0-4 把「修好」做出来：写操作接上

- **改什么**：至少一条修复路径端到端可写——MCP 服务连不上 → 面板内改配置或换启动命令 → 重测 → 显示通过。写之前自动备份原文件，写之后可一键回滚。`README.md:181` 现在写着「面板动作（现在页面只读，写操作接上之前这道门是唯一的写入面保护）」。
- **为什么**：第 3 节最后一段。只读面板交付的是「状况」，用户要的是「结果」。这也是第 4 节唯一那条判断标准的落点：修好之后不需要再打开任何配置文件。
- **验收**：在作者机器上故意制造一个真实的坏 MCP 服务（把启动命令改坏），从打开应用到修好 ≤ 5 分钟，全程不打开编辑器；原配置有备份；回滚后能回到坏状态。
- **安全约束（不可省）**：这是产品第一次获得写用户文件的权限。必须做到：写前备份到易失目录；只改自己解析出来的字段，不重排整个文件；失败即回滚并保留原文。这条没做完之前不要对外发内测版——它决定用户第一次就信任还是第一次就卸载。

### P1-1 解释「为什么不行」

- **改什么**：给每个未覆盖/失败项补一条人话原因和一条可执行动作。`README.md:92-93` 的实测事实是：配置声明 13 个客户端，`aios status` 只覆盖 10 个，未覆盖显示 `not-covered`；逐轴原因是「不存在」，因为配置只有行级 `limits[]` 与可选 `subagents.evidenceRef`。
- **为什么**：问题 6。用户看到 `not-covered` 会读成「有问题」或者「没问题」，两种都是错的，产品必须替他消歧。
- **验收**：每一个非 ok 状态都有一句为什么 + 一个下一步（按钮或可复制命令）。查不到原因时明说「尚未查明」，不编。

### P1-2 覆盖度不裁剪，改排序

- **改什么**：13 个客户端继续全支持，能力层不动。但首屏按**本机实际命中**排序：装了的在前，没装的收进「其他支持的客户端」。`home-workspace.tsx:39` 那个写死的「9 个服务配置实例」换成真实计数。
- **为什么**：覆盖度正是第 4 节 A 人群痛的理由，砍掉就没差异化了；但覆盖度不该占首屏，首屏只回答「你这台机器现在什么状态」。
- **验收**：在一台只装了 Claude Code 的机器上，第一屏全是 Claude Code 的真实信息，其余 12 个客户端不出现在首屏。
- **假设**：按命中排序比按全量平铺更能让用户立刻认出自己的机器。无数据，第 7 节验证。

### P1-3 空状态不是错误状态

- **改什么**：没装任何受支持客户端时，首屏给「装一个」的路径：列 2-3 个客户端 + 官方入口 + 装完重扫。不是空白，也不是示例。
- **为什么**：第 3 节那句「新买家屋子里是空的」。当前代码里根本没有这个状态，`demo-data.ts` 把它永久盖住了。
- **验收**：干净机器上首屏有明确文案和下一步，不出现假数据，也不出现红色错误。
- **注意**：这条不会把 C 人群（AI 新手）救回来。那正是第 4 节选 A 而不是 C 的理由。

### P1-4 三种事实分开显示

- **改什么**：配置已写入 / 历史证据 / 当前连接测试结果，三条各自带时间戳，不合并成一个「状态」。
- **为什么**：`README.md:79` 约定 1 的后半句已经这么要求，界面没做到。`home-workspace.tsx:36-44` 把「工具配置可读取」「服务配置实例」「连接测试状态」压进了同一行横幅。
- **验收**：任取一个服务，能分别回答：配置里写了什么；上次测是什么时候、结果如何；现在测得通吗。

## 6. 迭代阶段与退出标准

| 阶段 | 内容 | 产出 | 退出标准 |
|---|---|---|---|
| 0 测量（≤1 周） | `aios status --json` 各项真实耗时、冷启动到首条真实数据的秒数、当前安装成功率 | 一张数字表 | 有了可对比的 before 数字 |
| 1 变真（2-3 周） | P0-1 + P0-2 + P0-4 | 内测版：真实数据 + 能修 | 第 7 节 5 人中 ≥3 人完成「看清 + 修好」 |
| 2 能装（≤2 周） | P0-3 签名 + 自带运行时 | 可分发安装包 | 干净 Windows 虚拟机双击 ≤3 分钟见真实数据，无 SmartScreen 拦截 |

本计划内明确不做：托盘与自启、团队版/服务端/权限审计、macOS 公证先于 Windows 签名、把模型路由或 agent 编排搬进界面。

## 7. 用户验证（5-10 人，2 周内）

唯一目的：确认或推翻第 4 节那条假设——A 人群愿意为「跨客户端统一管理 + 一条命令修好」付费。

**找谁**：本机已装 2 个以上 AI 客户端、且至少配过一个 MCP 服务的开发者。不找同事，不找没用过 MCP 的人。

**怎么测**（每人 30 分钟，屏幕录制 + 出声思考，全程不讲解）：

1. 给他装好的包（阶段 2 之后）或直接给仓库（阶段 1 期间），只说一句「打开看看」。
2. 记录四个数：T1 多久说出「这是我机器上的东西」；T2 多久定位到坏掉的那个服务；T3 有没有主动点「修好」；T4 结束时还想不想去开配置文件。
3. 结束后只问行为，不问评价：
   - 「上次你的 MCP 连不上，你是怎么修的？花了多久？」
   - 「如果这工具刚才替你修好了，下次你还会自己改文件吗？」
   - 「你愿意为它付多少？按月还是买断？」——问完闭嘴等他自己说数字，不给选项。

**判定**：

- 通过：≥3/5 在 5 分钟内完成「看清 + 修好」，T4 全部为「不需要开配置文件」，且 ≥2 人主动给出价格。
- 多数人卡在 T1（认不出是自己的机器）→ 问题在 P0-2 和首屏文案，不是定价，改完重测。
- 多数人修好了但说「我还是会自己改文件」→ 第 4 节假设被推翻。停掉阶段 3，重做定位，别再往这个方向加功能。

**记录**：每人一条，写 T1-T4 的秒数/次数和他的原话。不许写「用户觉得不错」这类总结。

**假设**：5-10 人只能给方向性判断，给不了定价结论。定价要靠后续更大样本。
