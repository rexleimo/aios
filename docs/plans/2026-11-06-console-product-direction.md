# AIOS Console 产品改版：方向决策稿

状态：方向 A 已由用户确认，独立 `/prototype` 交互原型已实现；真实后端接线尚未实施。不替代 ADR 0008 已确认的配置所有权与客户端限制。
输入：用户反馈 app 难用、存在许多异常；用户确认 A，并指出很多私人项目记忆无法查看、记忆难以读懂；当前源码与 ADR 0008。
输出：已选产品方向、关键流程、跨项目记忆方案、验收标准与剩余能力缺口。本文是设计提案，未完成真机可用性测试。

## 1. 产品承诺

让开发者在一个地方看清并管理本机 AI 编码工具：给指定工具接入能力，知道是否生效，失败时能恢复。

主要任务依次为：查看已安装工具；给工具添加 MCP；为指定项目配置能力；浏览与维护多个项目的记忆；定位连接问题；查找最近操作。
记忆是一级产品能力；会话和用量为辅助信息。此次不新增聊天客户端、任务执行引擎、市场或请求网关。

## 3. 两种产品方向

| | A：本机 AI 工具管理器（推荐） | B：项目工作台 |
|---|---|---|
| 首页 | 已安装工具、需要处理的问题、最近操作 | 最近项目、当前项目工具与活动 |
| 主导航 | 首页 / AI 工具 / MCP 服务 / 记忆 / 活动记录；设置独立置底 | 项目 / 项目工具与扩展 / 项目记忆与记录；全局工具另设入口 |
| 默认操作 | 选择工具，再配置服务与生效范围 | 先打开项目，再配置项目所用工具 |
| 适用 | 经常在多个客户端间配置与排障 | 大部分时间围绕一个代码仓工作 |
| 代价 | 项目上下文仍需明确设计 | 需先建立可靠的项目选择、历史与切换机制 |

用户已选择 A。延续 ADR 0008 的本机管理定位，优先修复已有 MCP 闭环，并将跨项目记忆纳入核心范围。A 提供项目选择器；项目级写入必须选定项目。

## 4. 推荐的信息架构

- 首页：已检测的工具；需要处理的问题；最近操作。没有数据时引导检测，不显示虚构数字。
- AI 工具：已安装优先，可切换查看未安装；工具详情含概况、MCP、技能与集成、诊断。尚无管理动词的能力只读并说明原因。
- MCP 服务：按服务汇总，显示安装在哪些工具；可展开每个工具与生效范围的实例。异常可独立筛选。
- 记忆：浏览、搜索与维护已加入项目的记忆；当前项目与所选项目集合可切换，记忆阅读范围明确独立于配置写入目标。
- 活动记录：默认显示 GUI 操作；会话、用量放入明确命名的子视图，分别保留各自操作边界。
- 设置：外观、启动与连接信息、高级诊断；“能力声明”和完整接入矩阵移入高级区。

全局栏固定显示：当前项目（未选择时明示）、本机服务真实连接状态与重试入口。
操作中锁定工具与范围；切换项目不允许把进行中的操作悄悄改指向新项目。

## 6. 三条关键流程

### 添加 MCP

入口：首页工具卡 → 管理 → MCP → 添加；或全局 MCP 页 → 添加服务。

1. 填服务名称和连接方式（标准输入输出 / HTTP；仅展示后端确实支持的选项）。
2. 命令、参数逐项输入；环境变量逐项输入且值默认遮蔽。JSON 导入放高级入口。
3. 选择目标工具与范围：“此用户下的所有项目”或“仅项目 X”。项目未选时禁用项目范围并提供选择入口。
4. 预览变更：服务、目标工具、范围、会修改的文件、已有配置冲突、可恢复方式。预览不写盘。
5. 执行后逐项报告：配置已写入 / 连接测试通过 / 尚未测试 / 需要重启客户端 / 失败。禁止把写入成功当作可连接。
6. 部分成功时保留结果，只重试失败项。批量写入前须先证明各项有独立结果与可恢复记录；否则先支持单目标。

新增流程与已有实例详情分别呈现。删除、停用、接管始终绑定所选实例；不从另一个表单读取名称。

### 修复服务

点问题 → 看“发生了什么 / 影响哪个工具与范围 / 下一步”。只有可证明的原因才给确定结论。
可自动重试时提供重试；须用户登录或重启时明确交接；配置被外部修改时展示差异，不能覆盖。
失败保留用户输入、当前选中项和最近结果。原始错误与诊断命令在“技术详情”展开。

### 移除或停止管理

停用、从工具移除、交给用户自行管理是不同动作，不能共用含糊的“删除”。
对非 AIOS 管理条目先解释现状；只有存在后端能力的动作才能提供按钮。
移除确认显示工具、服务、范围；恢复依据实际备份与指纹，外部配置已变化时不强行回写。

## 7. 状态、文案与视觉

状态分开表达：配置（已读取/读取失败）、管理归属（AIOS 管理/自行配置/外部修改）、连接（测试通过/测试失败/尚未测试）、操作（执行中/完成/部分完成/需手动继续）。
历史落点验证只证明某次配置写入与恢复测试；不能当作当前服务在线状态。每次测试显示对象、时间与测试类型。

默认中文状态；机器 token、文件桶路径、哈希和原始 stderr 保留在技术详情及可脱敏导出的诊断里。
“接管”在按钮上写为“交给 AIOS 管理”，确认说明之后哪些配置允许被修改。

视觉建议：浅色默认，保留深色；中性背景、清晰边界、单一强调色；正常状态低噪声，异常集中提示。
主内容 14px 起，等宽字体只用于命令与路径；详情按需打开，不常驻占掉一半窗口。
键盘可达、焦点可见、状态不只依赖颜色；1024×768 可完成添加，窄窗改详情页。

## 8. 记忆专项：跨项目可达与可读

### 查证结果

- `apps/shell/ui/src/app/api/memory/route.ts` 的 `repoRoot()` 只选环境变量或启动路径；没有项目选择参数。
- 同一路径的 `run()` 把 `<项目>/scripts/aios.mjs` 当作可执行入口，GET 还用该文件是否存在决定能否读取记忆。普通项目不应需要携带 AIOS 源码。这是代码可确认的访问障碍；尚未逐一复现用户所有私人项目。
- `memory-browser.tsx` 空查询不展示最近条目，搜索时默认只读 10 条，并解析 CLI 人类可读文本。用户须先知道关键词才有内容可看。
- `data-pages.tsx` 仍突出事件、空间、候选、字符与反馈次数，正文直接显示长记录与事件 ID。
- `scripts/lib/environment/aios/state-root.mjs` 已有项目状态根解析器，支持 `AIOS_PROJECT_STATE_DIR`；不能只扫描固定 `.aios/memo` 路径。
- `scripts/lib/memory/memo/storage/base/normalizers.mjs` 已保留来源、引用、生效时间、候选与取代关系等字段；旧记录可能缺字段，展示不得补造证据。

### 入口与项目范围

记忆保留一级导航，默认打开当前项目的最近有效条目，不要求先搜索。提供“当前项目 / 选择项目 / 已加入的项目”阅读范围。

项目目录通过本机文件夹选择器加入；不要求公开仓库、Git 远程、上传或复制源码，也不要求项目存在 AIOS 程序。没有记忆的目录与无法读取的目录用不同状态表达。

维护本机项目目录清单，保存项目别名与稳定标识、真实路径和访问状态；同名项目用路径辅助区分。只读取用户选择的目录；如果有已有项目目录登记机制优先复用，尚未查证有完整可用注册表。可另行选择父目录批量发现，未选择前不全盘扫描。

目录失效时保留项目项并提供“重新定位”；遇外置状态根提供“指定记忆位置”。读取依照权威路径解析器与明确的项目映射，不能让启动进程继承的状态根把多个项目错误指向同一份数据。

读取已有项目不初始化、不迁移、不修改记忆；从项目列表移除只取消本机登记，明确保留原文件。

### 默认页面

```text
记忆    范围：[当前项目：harness-cli ▾]       [搜索当前范围] [加入项目]

项目                    最近记忆（默认无需关键词）       条目详情（按需）
harness-cli             Windows 启动入口的路径修复      记住了什么
我的私人项目 A          发布前需要完成的检查            原始事实与适用范围
我的私人项目 B          项目目录已移动，待重新定位      来源 · 时间 · 更新历史

```

以上条目标题均为布局示例，不代表读取到私人项目数据。记忆页所选阅读范围不会改变 MCP 配置的项目写入目标；从记忆跳转配置时需明确切换提示。

### 人可读的条目

列表先展示短标题、两三行内容预览、所属项目、记录时间与有效性；完整内容在详情保留排版。长内容可收起，ID 与机器字段放技术详情。

详情固定回答：记住了什么；适用于哪个项目/范围；来源是什么；何时记录/生效；是否已被后续事实更新。
来源确有会话、文件或证据引用时提供跳转；没有时显示“来源未记录”，引用失效则显示失效原因。不能把记忆时间当证据核实时间，也不能因为旧就判失效。

有明确取代关系时展示“已被更新”并链接新事实；没有有效性证据时只说“未发现更新记录”。待确认候选与生效记忆区分，旧版缺字段显示未知。

已有字段支撑的分组可直接使用；需求、决定、踩坑等语义主题由人或模型显式标注，不用文本关键词偷偷推断。未分类记录仍可正常浏览。

短标题优先已有标题或首段原文摘录；复杂记录仍保留全文。需要自然语言重写时产生可查看原文的摘要草稿，明确区分草稿与已确认内容；不静默改写持久记忆，不为阅读默认发送私人内容到外部模型。

### 人的操作与 AI 的召回分别设计

第一版保留“这条有用”和“更新这条事实”的既有动作，更新展示新旧对比，明确旧记录保留与召回影响。没有后端支持的归档/删除/固定按钮不先造出来。

查看范围、是否提供给其他项目的 AI、导出/同步是不同状态；本机聚合阅读不自动扩大 AI 的召回范围。项目 A 的写操作仍定位项目 A，不能仅凭相同 event id 操作；复合身份必须包括项目、空间、事件。

私人项目与 `agent_private` 不是同义词；现有 agent 访问边界照旧生效。需要本机所有者查看私有 agent 数据时，必须通过已有可验证的所有者读取契约，未具备时显示限制，不能借新 UI 绕过。

搜索与缓存、固定记忆和正文、写入结果均按项目隔离。切项目后旧请求不得覆盖新项目内容，错误不能伪装成“暂无记忆”；多项目部分不可达不阻断可达项目。

### 可行性与待补能力

复用项目状态根解析、已有事件列表与搜索、来源/取代字段、useful/supersede 动作。需要新增或补齐：安装入口与项目根分离、已加入项目的可信选择契约、结构化条目读接口、分页/翻页、项目隔离缓存及写操作校验。

无关键词浏览优先使用现有 `listMemoEvents` 能力；完整分页与排序契约须实施前查证。不同项目可用的存储/旧版布局由解析器检查，无法识别就显示具体限制，不能返回假空列表。

### 记忆验收场景

1. 两个私人项目无需公开或携带 `scripts/aios.mjs`，加入后均能读其已有记忆，文件无改动。
2. 不输入关键词即可看到最近条目，可继续加载；同名不同目录项目与同 event id 条目不混淆。
3. 非开发者能从详情指出记住的事实、所属项目、记录时间、来源及是否已更新；来源缺失不编造。
4. 目录移动、权限不足、无记忆、外置状态目录分别有准确状态和恢复入口；一个失败不拖垮全部项目。
5. 项目切换与搜索并发不串结果，更新动作绑定原项目，缓存不跨项目污染。
6. 聚合阅读不改变 agent 召回范围、不上传私人内容；原文、阅读摘要和持久事实有明确区分。

## 9. 优先级与验收

P0：启动失败有恢复入口；连接状态有真实依据；目标工具/项目/范围始终可见；新增与已有操作分离；加载和异常不阻断整页；私人项目记忆可选择并读取、空查询可浏览、默认正文易读。
P1：添加→预览→写入→测试→结果闭环；移除与恢复；外部修改保护；活动记录可追溯。
P2：服务跨工具汇总、筛选、快捷操作；技能管理须另开能力工作项，不能只补按钮。

验收用真实桌面完成以下场景，并记录屏幕与配置前后结果：
1. 首次启动，不懂 AIOS 内部术语也能找到工具并开始配置。
2. 参数含空格、环境变量有值，预览不落盘，写后正确读回。
3. 未选项目、未装客户端、空配置、只读落点均有准确提示和合理入口。
4. 服务启动失败、服务端断开、网络异常后保留上下文并能重试。
5. 用户在预览后改配置，提交检测冲突且保留用户内容。
6. 写入成功但未握手时显示“尚未测试”；历史证据不冒充在线状态。
7. 移除正确实例并恢复；恢复遇新改动时不覆盖。

## 10. 当前决定与下一步

已确认 A“本机 AI 工具管理器”，不再重复要求用户选择方向。用户的新约束：很多私人项目记忆不可查看，且现有记忆不便人理解。记忆提升为一级入口，项目接入与可读性纳入 P0。

当前原型覆盖工具管理与记忆页：私人项目选择、最近条目、事实详情、更新关系、不可达恢复，以及 MCP 预览与分离结果。实现与验证见 `docs/plans/2026-11-06-console-prototype-verification.md`。后续真实后端仍按本文 MCP 七项与记忆六项验收，不把示例原型当作已连接真实后端。

尚未确认：用户各私人项目的具体异常、启动与刷新实测时延、新流程任务成功率；通过实际走查补齐。用户没有授权全盘扫描或向外部模型发送私人记忆。
