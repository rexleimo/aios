# 0011 — 意图分流落地范围：模型恒为 Auto，任务始终跑在意图模型上

- 状态：已接受（2026-11-19 用户修正范围：「用户使用我们的网关时模型始终是 auto，发起任务时任务都可以在用户设置好的意图分流模型中执行，类似 oh-my-opencode 的角色编排指定不同模型」）
- 关联：ADR 0004（auto mode 决策升级）、ADR 0010（就地外科改写真实配置）

## 需求（用户原话口径）

用户把客户端接到网关、模型恒为 Auto。此后用户发起任何任务，该任务都在他配置好的意图分流的那个模型上执行——像 oh-my-opencode 按角色给不同模型那样。不需要系统判断哪家便宜。

## 决策

### 1. 范围只到「意图分流按预期生效」

不做：价格表、token/cost 记账、成本档自动挑选、Claude Code auto mode（权限审查）兼容、`own` 模式客户端（gemini/grok/workbuddy/zcode/qoder）适配、per-client 独立意图表、分类器工程增强（答案缓存、失败休息、in-flight 去重、可配置超时、userWords 过滤、turnBefore 上下文）。这些都不服务「任务跑在指定模型上」这一条。

「便宜」由用户自己判断并写进意图描述；系统只负责按意图把轮次送到对应模型。

**实施细节**: 详见 [`docs/plans/2026-11-19-intent-routing-implementation.md`](../plans/2026-11-19-intent-routing-implementation.md) — 包含文件级/函数级修改清单、数据结构、测试计划、验证命令，供其他模型实现代码。

### 2. 现状：链路已通，但「始终」有四处不成立

已核实代码路径（`routing/intent.mjs`、`gateway/compatibility/proxy.mjs`、`gateway/router.mjs`、`connect/editors.mjs`）：

已成立的部分：
- `connect` 把客户端模型写成 `aios-auto`（claude 的 `model` 与 `ANTHROPIC_*_MODEL`、pi 的 `defaultModel`）；
- 普通模型名不被当作显式目标（`parseWireTarget` 对非 `aios-*` 值返回 null），所以不会绕过分类器；
- 新用户轮分类，工具续轮沿用本轮意图；
- 显式 `aios/model/...` 目标与 `x-gateway-role` 头显式绕过。

不成立的部分（按对「始终」的破坏力排序）：
1. **无 session 头时工具轮重复分类**。`x-gateway-session` 缺失�� `sessionKey` 为空，走 `latestTurnUserText`——它会回溯到上一条用户消息，导致每个工具轮都重新提问分类器：多花钱、多延迟，分类不稳定时同一任务会在模型间跳动。
2. **意图模型不可用时静默回落**。`resolveGatewayTarget` 的候选链是 `[intentModelId, ...chain]`，意图模型无凭据/被判 down 时直接落到默认链，任务跑在非意图模型上且不报错。
3. **任一意图不可路由则整份意图分流静默失效**。`qualifiedIntentConfig` 逐个校验所有 intent 的目标可达，任意一个模型缺凭据（或网关可用模型少于 2 个）就返回 null，全部请求回到默认路由，界面无提示。
4. **分类失败/低置信度回落默认路由**。这是 fail-open 的设计，与「始终在意图模型执行」冲突，需要显式裁定——见决策 4。

### 4. 回落是允许的，但不许静默（用户裁定 2026-11-19）

「任务跑在意图模型上」是**尽量**，不是硬保证：意图模型缺凭据、被判 down、分类器失败或置信度低于门槛时，任务仍然完成，走默认路由。但回落必须在决策记录与路由图中可见：写明是哪一环失败（无凭据 / down / 分类失败 / 低置信度）以及回落到哪个模型。未标注的回落视为缺陷。

理由：硬失败会让用户在一个模型临时挂掉时丢掉整个任务，代价远大于跑错模型；而静默回落会让用户以为意图分流在生效、实际没有，那是更坏的假象。

### 3. 第一切片

**任务级粘滞**：任务一旦开始，本轮及其全部工具轮固定在同一个意图模型，不重复分类、不中途换模型。用可复现的会话键（session 头缺失时从会话内容派生）承载，而不是回溯历史用户文本。

## 非目标

- 意图表携带 effort、嵌套路由组、分类器走网关自体（failover/用量归集）。
- 零配置意图模板（缺价格数据无法自动挑成员）。

## 验收标准（用户可观察行为）

1. 客户端接入后模型恒为 Auto，用户发起任务，网关把它交给该意图配置的模型。
2. 同一任务的后续工具轮不再提问分类器，也不换模型。
3. 意图模型缺失或不可用、分类器失败或置信度不足时，任务照常完成并走默认路由，且决策记录与路由图写明失败环节与回落目标。
4. 回落不改变客户端的模型选择：客户端仍然恒为 Auto，用户不需要为此改任何配置。
4. 显式指定模型或角色的请求仍绕过分类器。

## 后果

- 意图分流从「骨架可用」推进到「判断可信且不会中途漂移」。
- 不引入价格数据意味着文案只能说「这轮交给 X 模型」，不能说「更便宜」。
